## 2. 本次已补齐的可运行链路

| 模块 | 当前能力 | 主要证据 |
|---|---|---|
| SDK 生命周期 | 延迟初始化、enabled、flush、shutdown、atexit；建库失败旁路降级 | `tests/test_sdk.py`, `test_sdk_faults.py` |
| 拦截 | 同步/异步 trace/tool、session、llm handle、瞬时 log_step、嵌套 parent | `tests/test_sdk.py` |
| 异常与流式 | 返回值/异常保持原语义；CancelledError 记录；部分输出保留；usage 优先，缺失标估算 | SDK 测试及 demo SSE 测试 |
| 基础脱敏 | 敏感键、环境密钥、Bearer 和常见 sk 格式；输入输出捕获开关 | `test_capture_switches_and_secrets`, `test_sdk_faults.py` |
| 离线示例 | 课程答疑、笔记整理、流式 Mock、可控工具失败、真实兼容 API 适配入口 | `tests/test_demo.py` |
| 造数 | seed/n/db 参数，可复现 UUID/时间/Token，批量直接落盘 | `tests/test_query.py`, `test_cli.py` |
| 查询与 API | 只读 SQLite；列表/详情/统计/健康；参数校验、时区归一、404/422/503 | `tests/test_query.py`, `test_server.py` |
| 查看器 | Vue 3 + Element Plus + ECharts；过滤/排序/分页、瀑布图、完整字段、失败图表 | 生产构建、浏览器走查 |
| 工程 | Python 双平台 CI + 前端构建任务；静态文件和 Mock 数据打包配置 | `.github/workflows/ci.yml`, `pyproject.toml` |

`llm()` 一直返回 SpanHandle，由业务选择 MockClient 或真实 API；不在 SDK 中隐式替换用户的
调用。Mock 数据置于 `agenttrace/data/` 以便随 wheel 分发。默认示例离线运行。

统计口径：成功率 = 成功任务 / 已结束任务（running 不进分母）；平均步数按全部 Span
计数，包括根事件与瞬时步骤；失败类型按失败 Trace 的异常类型计数，一个任务只计一次。
Token 不自动换算成金额。

## 3. 已复现并修复的缺陷

| 编号 | 触发与影响 | 修复与回归 |
|---|---|---|
| BUG-01 | 写线程已取走队列但事务尚未提交，flush 返回 True | 同时等待 in-flight 写入；阻塞存储用例复现并通过 |
| BUG-02 | 空队列超过 flush_interval 后 wait(0) 空转 | 无事件时 Condition 阻塞，首次入队唤醒 |
| BUG-03 | 同一 Span usage 更新两次，被累计两次（19 误变 34） | 按 Span ID 做增量；Trace 结束后清理聚合内存 |
| BUG-04 | 64 KiB 截断后再次 JSON 转义，字段仍达到 119246 bytes | 按最终 JSON 字节数二分，回归断言 <=65536 |
| BUG-05 | Trace 耗时用墙上时钟、Span 用单调时钟，改时可导致不一致 | Trace/Span 均使用 monotonic；时钟跳变回归 |
| BUG-06 | shutdown 超时就关库，后台线程可能使用已关闭连接 | 超时保留 runtime/连接，阻止切换到新配置；故障用例验证 |
| BUG-07 | 凭据可能出现在工具参数/返回/异常 | 结构化脱敏、环境密钥快照及 capture 开关；SDK 故障日志不打印底层异常内容 |
| BUG-08 | SSE 在完成信号前 EOF 会被误标成功 | 无 DONE/finish_reason 时失败，finally 保存部分输出；正常/断流两种回归 |

BUG-02 的空闲行为有代码审查证据；没有把短时 CPU 采样写成已完成的长时间压力测试。

## 4. 验证结果与复现

环境：Windows，Python 3.11.9，Node.js 24.19.0。2026-10-15 本地运行：

```bash
python -m pip install -e ".[dev,server]"
ruff check .
pytest --cov=agenttrace --cov=server --cov-fail-under=70 --cov-report=term-missing
cd web
npm ci
npm run build
```

- Python：62 passed，SDK + server 覆盖率 94.85%，ruff 无告警。
- FastAPI TestClient 依赖组合产生一条 httpx 将被弃用的提示；当前用例均通过，后续依赖维护需处理。
- 前端生产构建通过；当前全量组件引入使主 JS 约 1.47 MB（gzip 约 488 KB），Vite 提示
  chunk 过大。尚未将该提示计作功能失败，后续可按需引入组件并延迟加载统计图。
- 浏览器走查：1000 条合成任务 + 1 条离线示例；失败过滤为 198 条，翻页生效；详情直接
  刷新有效；流式完整输入输出与 usage 可见；失败标红、统计图与基础窄屏布局正常。
  浏览器未捕获到 error/warn。时间范围格式和不同时区等价输入由 API 测试验证。
- 截图：[失败时间线](screenshots/viewer-timeline.jpg)。数据为明确标注的合成数据。
- 远程 GitHub Actions 本次未触发，不能把本地成功表述为远程 CI 全绿。
- 本地 wheel 已构建到 `dist/agenttrace-0.1.0-py3-none-any.whl`。执行
  `python scripts/verify_wheel.py dist/agenttrace-0.1.0-py3-none-any.whl` 通过：确认 Mock 数据、
  HTML/JS 静态资源进入安装包；使用 `python -I -S` 从 wheel 独立导入 SDK、回放 Mock、
  记录与查询 SQLite，未加载 FastAPI 等第三方模块。不是只在 editable 源码环境冒烟。

Windows 沙箱限制本地 socketpair，原有 asyncio 用例会卡在创建事件循环；正常环境运行后
通过。这属于测试环境限制，没有为规避它删除/跳过协程测试。

性能初测复现：

```bash
python scripts/benchmark.py --output docs/performance-baseline.json
```

100 次、单个入口 Trace、每次模拟等待 20 ms：基线 20.6496 ms，埋点后 21.0660 ms，
额外开销 2.02%，flush 成功。1000 条任务、每条 6 个 Span，查询 1000 条重复 10 次，
平均 8.7069 ms、最大 11.3445 ms。原始结果见 `performance-baseline.json`。
此前约 12.63% 的初测暴露了每字段扫描环境变量的开销，改为每个任务一次不可变快照后改善。
此结果只覆盖指定模拟负载，**不代表 NFR-1 / NFR-2 最终验收通过**；尚需真实多步骤负载、
短任务/长任务/并发对照，以及 HTTP 与浏览器冷启动计时。

当前未改动 FR-2.4 的承诺，也未把“最后一条”解释成“最后一批”。
下一轮首先处理 P0，再扩充压力/性能/验收证据；随后完成课程制品。

支持边界：必须 await 根任务内启动的异步子任务；线程池上下文传播、生成器装饰器未支持。
init/shutdown 应在任务外调用。基础脱敏不是通用 DLP，环境密钥在任务开始时快照，自定义
敏感输入应关闭 capture。Mock 应答按模型顺序消耗，耗尽明确报错，不假装执行真实推理。
