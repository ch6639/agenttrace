# AgentTrace 需求调研 · 访谈提纲与痛点记录

> 用途：M0 需求调研。访谈 2–3 名写过 Agent 或用过 LLM API 的同学，痛点结论回填 SRS 附录 A，并为 F1–F6 功能假设提供证据。
> 配套文档：`SRS初稿-AgentTrace.md`（附录 A）、`项目计划-Agent可观测性工具.md`（第 9 节行动项 2）

---

## 一、访谈执行说明

| 项目 | 建议 |
|------|------|
| 对象与人数 | 2–3 人；最好覆盖不同技术栈：一人用框架（LangChain 等），一人裸调 OpenAI 兼容 API，一人用 Dify/Coze 等低代码平台更佳 |
| 时长 | 30–40 分钟，半结构化：按提纲顺序，允许追问展开 |
| 方式 | 线下面聊最佳；线上语音也可。**征得同意后录音**，事后整理 |
| 核心原则 | **多问"上一次"，少问"你会不会"**。问事实和经历（好挖、可信），不问对未来产品的想象（会被客气话污染） |
| 顺序纪律 | 概念验证（第五部分）必须放最后。先介绍产品会引导访谈对象，后面所有回答都作废 |

**追问三板斧**（挖到具体事件后反复用）：
1. 什么现象让你发现出错了？（怎么发现的）
2. 你当时做了什么来定位？（怎么定位的，花了多久）
3. 最后原因是什么？在哪一行代码/哪一步？

## 二、访谈提纲

### 第一部分：背景摸底（约 5 分钟）

> 目的：确认对方是目标用户（SRS 2.2），摸清技术栈（影响 F1 拦截方式、框架集成非目标）。

1. 先介绍一下你写过或正在写的 Agent / LLM 应用？什么场景？（课程作业 / 比赛 / 个人项目 / 实验室）
2. 技术栈是什么？——裸调 OpenAI 兼容 API（openai sdk）、LangChain / LlamaIndex、Dify / Coze 低代码、其他？
3. Agent 带几个工具？最复杂的一次任务大概跑了多少步、多少轮 LLM 调用？
4. 用的是流式输出（SSE）还是一次性返回？为什么？

### 第二部分：关键事件——最近一次调试经历（约 10 分钟，核心）

> 目的：验证"Agent 是黑箱、失败难定位"（SRS 1.2 背景、FR-2.x、FR-4.2）。这是全场最重要的一段，值得花一半时间。

5. **讲讲你最近一次 Agent 出错或结果不符合预期的经历？**（开场只问这一句，剩下全靠追问）
   - 追问：什么现象？隔了多久才发现？
6. 你当时是怎么定位问题的？
   - 追问：print 补丁？翻日志？加断点重跑？直接把 LLM 返回打印出来看？
7. 定位过程中最烦的是哪一步？从"发现不对"到"找到原因"隔了多久？
8. 有没有遇到过**重跑一次结果不一样**、没法复现的情况？怎么处理的？
9. 有没有遇到过 LLM 返回了东西、但后面工具调用静默失败（没报错也没结果）的情况？

### 第三部分：成本与过程感知（约 5 分钟）

> 目的：验证 Token 成本不可见（FR-2.1、F5 统计总览）是真痛点还是伪需求。

10. 你知道自己 Agent 跑一次任务大概花多少 token / 多少钱吗？怎么知道的？（看控制台返回？算账？不知道？）
11. 有没有关心过"这个任务到底走了几步、每步干了什么、时间花在哪"？
12. 如果要给这门课的作业控制 API 花费，你会想要什么样的信息？

### 第四部分：现有手段与替代品（约 5 分钟）

> 目的：搞清竞品认知（为什么不用 LangSmith / Langfuse），验证"零部署、≤3 行接入"（FR-1.1、NFR-4）是不是真门槛。

13. 有没有用过或听说过 LangSmith、Langfuse、Phoenix、OpenTelemetry 这类工具？
    - 用过的：为什么选它？哪里不爽？
    - 没用过的：为什么没用？（不知道 / 嫌部署麻烦 / 要注册账号 / 觉得用不上）
14. 如果要给你现在的 Agent 加上"运行过程记录"，你能接受多大的接入成本？——改几行代码？装多重的依赖？要不要起服务？
15. 演示/交作业时不能联网或不想烧 API 钱，你怎么办的？（验证 FR-1.3 / FR-6.2 Mock 模式的价值）

### 第五部分：概念验证（约 3 分钟，最后进行）

> 目的：概念回测——不问"你想不想要"，只问"它能不能解决你刚才说的那个问题"。

16. （30 秒介绍）"我在做一个工具：你的 Agent 加两三行代码，它每次运行的 LLM 调用、工具调用、token 消耗就全被记下来，存本地 SQLite，网页上能按时间线回放每一步，失败的步骤标红。"
    然后问：**如果这个东西早就有，你刚才讲的那个问题会不会更快解决？具体是哪一点帮到你？**
17. 这个工具里你觉得哪个功能最没用、可以砍掉？（验证第 7 节非目标）
18. （演示载体验证）你平时会用 LLM 做课程学习相关的事吗——课程答疑、把答疑内容整理成笔记？（对应 F6"课程学习助手"的选题合理性）

### 收尾

19. 关于写 Agent 的痛苦，还有什么你觉得我应该问但没问的？
20. 致谢；询问是否方便后续演示时再联系。

## 五、访谈技巧备忘

1. **沉默是武器**：对方答完停两秒，往往自己接着补充最有价值的细节。
2. **警惕客气话**："挺好的""应该会用"不算证据，追问"上一次你是什么时候、怎么做的"。
3. **警惕全能方案**：对方说"要是能自动帮我修好就好了"——记下来放展望，不进本期需求。
4. **记录原话**：SRS 附录里一句带场景的原话（如"我也不知道它中间调了几次工具，反正最后不对"）比十句转述有说服力。
5. 访谈对象推荐渠道：课程群、实验室同门、之前一起写过课设的同学；优先找**真的踩过坑交付过东西**的，而不是只跑过 demo 的。
