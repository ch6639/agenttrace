## 1. 项目定位

**一句话**：一个 Python SDK + Web 查看器。开发者加几行代码（装饰器），即可完整记录并回放自己 Agent 的每一步运行——LLM 调用、工具调用、决策步骤、Token 消耗、失败详情。

**解决什么问题**：Agent 系统是"技术黑箱"——课件明确指出 AI 生成代码带来"确认与验收难题"和"认知外包"风险；SWEBOK v4 新增"软件工程运营"知识领域。本工具让 Agent 的运行过程**可见、可查、可回放、可量化**。

## 2. 系统范围

### MVP 功能（验收标准逐条可测）

| 编号 | 功能 | 验收标准 |
|------|------|----------|
| F1 | 非侵入式拦截 SDK | 装饰器/上下文管理器接入 ≤3 行代码，不改动 Agent 业务逻辑 |
| F2 | Trace 数据模型 | 一次 Agent 任务 = 一条 trace；LLM 调用/工具调用/步骤三类事件按树形时间线组织 |
| F3 | 持久化存储 | SQLite 落盘，进程重启后 trace 可查 |
| F4 | Web 查看器 | trace 列表页 + 时间线详情页（失败标红、耗时/Token 可见） |
| F5 | 统计总览 | 总 Token 成本、成功率、平均步数、失败类型分布 |
| F6 | 示例被测 Agent | 自带"课程学习助手"双工具 Agent（课程答疑 + 笔记整理，LLM 可用 mock 回放模式离线运行）作为演示载体 |

### 明确非目标（写进 SRS，防范围蔓延）

- 不做分布式/多进程追踪
- 不做 LangChain 等框架深度集成（列为展望）
- 不自研图表，前端用现成组件库
- 不做用户系统/权限

## 3. 系统架构

```
┌──────────────────┐
│  示例 Agent 应用   │  examples/demo_agent
│  （被观测对象）    │
└────────┬─────────┘
         │ ≤3 行接入（装饰器）
         ▼
┌──────────────────────────────┐
│  agenttrace SDK              │
│  ├─ interceptors  拦截 LLM/工具/步骤 │
│  ├─ model         Trace/Span 数据模型│
│  └─ storage       持久写入 SQLite    │
└──────────────┬───────────────┘
               ▼
          SQLite（trace.db）
               ▼
┌──────────────────────────────┐
│  server：FastAPI 查询服务      │  /traces  /traces/{id}  /stats
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│  web：单页查看器（Vue 3）       │  列表 + 时间线回放 + 总览
└──────────────────────────────┘
```

**仓库结构**：
```
agenttrace/
├── agenttrace/        # SDK 包
├── server/            # FastAPI 服务
├── web/               # 前端查看器
├── examples/          # demo agent（演示用）
├── tests/             # pytest 单元+集成测试
├── docs/              # SRS、设计文档、测试报告（另存 Word 版）
├── models/            # PlantUML 源文件（用例图/组件图/类图/时序图）
└── .github/workflows/ # CI（GitHub Actions：lint + test + coverage）
```

## 4. 技术选型（附理由，写进设计文档）

| 项 | 选择 | 理由 |
|----|------|------|
| 语言 | Python 3.11+ | Agent 生态主流；课件/招聘要求均点名 Python |
| SDK 依赖 | 近零依赖（标准库优先） | 降低接入成本，本身就是卖点 |
| 存储 | SQLite | 单文件零部署，够用 |
| 服务 | FastAPI | 自动 OpenAPI 文档，省一页接口文档工作量 |
| 前端 | Vue 3 + Vite，图表用 ECharts | 单页应用，最快路径 |
| 测试 | pytest + coverage | TDD 支撑 |
| CI | GitHub Actions | 提交记录+CI 徽章=过程证据 |
| 建模 | PlantUML | 纯文本=天然"可编辑源文件"，满足作业第四条 |

## 5. 开发方法与 AI 协同策略

**方法**：单人 Scrum（1–2 周一个 Sprint）+ 核心模块 TDD。

**人机分工原则**（报告核心章节素材）：
- 人负责：数据模型设计、架构权衡决策、测试用例设计、AI 产出审查
- AI 负责：样板/适配代码、测试数据、前端页面骨架、文档初稿

**AI 协同证据留存**（每个 Sprint 更新）：
1. 关键 prompt 及其迭代版本（保留失败的第一版）
2. 构建的上下文说明（给了 AI 哪些文档/代码/约束）
3. AI 产出的人工修改 diff（前后对比截图）
4. 哪些产出被拒绝及原因

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| demo agent 依赖真实 LLM API（网络/费用/密钥） | SDK 内置 mock 回放模式，离线可演示；现场演示不赌网络 |

| 范围蔓延 | 第 2 节"非目标"清单是硬约束，新想法一律进"展望"章节 |
| AI 生成代码质量隐患（课件：bug 多 41%） | 核心 trace/span/存储模块 TDD；CI 强制测试通过才合并 |
